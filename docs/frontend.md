# 前端渲染层

## 范围

React 渲染层在 `src/renderer/`。桌面版启动时通过 Electron preload 暴露的安全 API 读取真实状态；浏览器预览时使用本地演示数据，方便不启动 Electron 也能看界面。

## 结构

- `App.tsx`：组合页面、维护交互状态、连接 Electron API，并在浏览器预览时提供演示数据。
- `types.ts`：定义日志状态、牌库、事件流、对手概览等前端数据结构。
- `components/TopBar.tsx`：顶部日志状态和主要操作。
- `components/DeckPanel.tsx`：我方牌库、剩余数量和抽牌状态。
- `components/CardDetailBody.tsx`：复用卡牌图像、费用、攻血、效果文字和关联牌详情。
- `components/CardHoverPreview.tsx`：卡牌鼠标悬停预览；主窗口使用页面内固定定位，置顶小窗通过独立透明预览窗向外展开，避免被小窗宽度挤压；置顶小窗预览刷新时用鼠标坐标确认仍在卡牌行内，避免独立预览窗导致系统 `:hover` 短暂丢失后闪烁；卡牌资料晚到但鼠标仍停在原行时会自动补开详情；鼠标真正离开、窗口失焦或刷新中断后会自动隐藏。
- `components/EventFeed.tsx`：实时事件流。
- `components/OpponentPanel.tsx`：对手职业、回合概览和已出牌列表。
- `components/ArenaPanel.tsx`：竞技场当前候选牌、版本评分、已选张数和自动生成的竞技场牌库。
- `components/ArenaChoiceOverlayPanel.tsx`：竞技场三选一时自动出现的鼠标穿透数据条，按游戏内三张候选牌顺序显示三项指标。
- `components/OverlayPanel.tsx`：可复用置顶小窗组件，只接收转换后的视图数据，不直接读 IPC。
- `components/LadderDeckRecommendationPanel.tsx`：左侧天梯推荐窗，显示模式、本机炉石版本、卡组名、职业、胜率、场次、来源、更新时间和紧凑牌表；牌表内部滚动，复制按钮固定在底部。版本读取、数据源、网络、数据校验、当前补丁无数据和缓存过期分别显示准确状态。
- `ladderDeckRecommendationStyles.css`：与右侧记牌器一致的深蓝黑紧凑样式，覆盖约 `210x500` 默认窗口和 `190x400` 最小窗口。
- `overlayView.ts`：把 `PublicTrackerState` 派生成置顶小窗视图数据。
- `overlayStyles.css`：实战置顶小窗样式。
- `cardHoverStyles.css`：缩略图、悬停预览和生成/关联牌列表样式。

## 已接入的桌面 API

- `discoverLogs()`：扫描常见炉石日志路径。
- `selectLogPath()`：手动选择日志文件或目录。
- `start()` / `pause()`：开始或暂停监听。
- `importDeck()`：兜底导入炉石卡组代码、炉石导出文本或手写卡组列表；主流程不依赖手动导入。
- `scanCollectionDecks()`：读取炉石“我的收藏 / 套牌”里的本机套牌摘要，供卡组工具页面展示。
- `importCollectionDeck(deckId)`：把收藏套牌导入为当前卡组，并返回新的记牌状态。
- `ensureLogConfig()`：写入炉石日志配置。
- `toggleOverlay()`：打开或关闭置顶小窗。
- `toggleOpponentOverlay()`：打开或展开独立对手记牌器；展开状态下再次操作会折叠为入口，不把折叠误报成窗口消失。
- `minimizeMain()`：最小化主程序，不影响两个置顶小窗。
- `showCardPreview()` / `hideCardPreview()`：置顶小窗悬停卡牌时打开或隐藏独立卡牌说明窗；只传当前卡牌资料和悬停位置，不新增日志读取路径。详情窗显示时由主进程接收 `Option+Q`，固定后暂停自动关闭，允许鼠标移入详情窗滚动；再次按下取消固定。
- `listCardLibrary(query)`：按关键词、职业、类型和页码读取本地卡牌数据库；主程序首次打开“卡牌数据库”时调用，搜索输入延迟 220ms，筛选和翻页立即刷新。
- `getMatchHistory()`：读取已经过后台校验的本机对局历史；只在主窗口开放，置顶小窗没有此能力。
- `onUpdate()`：接收后台推送的记牌状态。

后续如果加入更多真实字段，IPC 数据进入 React 前仍应做运行时校验，避免日志解析异常直接污染界面状态。

星空投影球的详情会在卡图和正文下方占满整行，显示“本局已施放法术（N）”。列表按实际施放顺序保留重复法术；本局尚未施放法术时明确显示空状态。主窗口悬停和置顶小窗的独立详情窗共用同一份详情数据。

随机施法牌的详情把“理论候选牌池”和“本次实际施放”分开。理论牌池显示当前卡库可匹配的范围和数量；实际结果按日志中的真实次数展示，双倍施放不会固定成 5 张，古神套古神时子结果显示在触发它的古神下。超大理论牌池分批展开，避免打开详情时一次渲染数千张牌。

## 置顶小窗

`OverlayPanel` 已接入 `?overlay=1` 小窗入口。牌库、手牌、场上、奥秘、墓地、移除、疑似烧毁和已使用卡牌行使用不含列表序号的稳定身份，实时移除前序卡牌时不能重建仍在悬停的后续卡牌。入口先调用：

```ts
const overlayView = toOverlayPanelViewModel(publicTrackerState);
```

再把结果传给组件：

```tsx
<OverlayPanel view={overlayView} onClose={toggleOverlay} />
```

它展示剩余牌库、已抽统计和监听状态。完成首次读取后，持续监听统一显示“监听中”，不能继续显示“读取中”造成卡住的假象。竞技场状态显式携带 `confirmedCount` 和 `unresolvedCount`。竞技场处于选牌、重选或等待开局时，主小窗与普通记牌器互斥，只渲染按费用排列的“选取率 / 卡牌 / 影响”三列表，完成选牌后阶段栏明确显示“等待开局”；进入 `playing` 后不再把统计字段交给界面，并恢复普通记牌器。对手已出牌独立使用 `?opponent-overlay=1` 小窗，按卡牌合并数量、过滤日志字段伪记录，并保留缩略图和鼠标悬停卡牌详情；数据全部来自现有 `PublicTrackerState`，没有新增日志读取路径，也不主动访问网页。

双方场攻不再塞进对手小窗的大按钮，而是在透明战场层按英雄位置各显示一枚约 `32×32` 的圆形“小剑 + 数字”计数。疲劳、尸体和已用法术只在有真实值时显示为约 `26×26` 的小圆计数，不包成大面板。有对方奥秘时，每个实体保留独立的问号槽位；点击槽位展开该槽位候选。仍可能的候选保持深色高亮，已被实战动作排除的候选使用白底深色字、删除线和“已排除”文字，不能只靠颜色区分。展开窗口可像我方记牌器一样缩到 `100×150`；窄窗保留标题、状态点和折叠按钮，候选区和出牌区分别内部滚动，不能产生横向溢出。

对手小窗默认使用约 `250×170` 的紧凑尺寸。关闭按钮把它折叠成可拖动、可点击恢复的问号入口，不销毁窗口；新增奥秘会更新这个入口，但不会强制把用户已折叠的窗口展开。展开位置和大小保存在本机，主窗口的对手入口可以恢复它。

场攻数据继续在后台计算；新用户默认关闭场攻悬浮按钮，只有在设置里主动开启后才显示，自动验收仍可通过专用入口验证透明层。

主进程常驻一个透明的 `?arena-choice-overlay=1` 窗口。日志或本机画面识别到三张竞技场候选牌，并且炉石是当前前台应用时，它自动显示在游戏卡牌下方；选完、离开选牌、退出竞技场或切到其他应用后立即隐藏。窗口不接收鼠标点击，不影响在炉石中选牌。HearthArena 简中/繁中官网数据只作为“评分”来源；真实来源只有胜率时，第二格会明确写为“胜率”，不会把它伪装成选取率；传说团队没有 HearthArena 评分但有 Firestone 数据时，每张明确显示“评分暂无 / 入选胜率 / 选取率”。第三格优先显示真实 `12胜率`，公开源没有 12 分桶时显示 `6+胜选取` / `高胜选取`，完全没有高胜数据时显示 `高胜数据`。

## 日志未就绪展示

前端把 `missing-log` 和当前监听路径为 `Player.log` 视为“无法读取真实对局”。这时主界面和置顶小窗都必须优先提示：

> 先点“修复日志”，然后重启炉石/开始一局。

在这个状态下不要展示默认示例卡组、抽牌记录或对手出牌列表，避免用户误以为示例数据是真实数据。

## 收藏套牌同步

卡组工具是左侧一级导航，右侧页面同时提供手动粘贴和“从收藏读取”。页面沿用主程序的黑金面板、铜色边框和金色主按钮，不再创建遮罩弹窗。前端只负责调用 preload API、展示套牌摘要和触发导入，不在渲染层解析炉石收藏文件。

后台会在启动和开始监听前自动同步收藏套牌，并把解出的牌表交给记牌引擎做自动匹配。卡组工具页是手动兜底和检查入口。

竞技场进入选牌后，后台状态会自动切换到竞技场面板。主窗口面板继续展示当前候选牌的评分、缩略图、卡牌详情、最近选择和当前牌库；右侧置顶小窗在开局前改为 Firestone 三列表，不与普通记牌器同时出现。实际对局开始后，普通牌库面板继续使用这套竞技场牌库进行记牌。渲染边界会校验竞技场状态、牌数、待识别数和可选统计字段，拒绝矛盾载荷；之后收到合法实时状态时会清除旧的校验错误。

列表展示套牌名称、卡牌数或“卡组代码”、来源路径、更新时间和 warning。导入成功后停留在卡组工具页，使用后台返回的 `PublicTrackerState` 更新主界面并显示成功状态。

浏览器预览没有 Electron preload API 时，只显示安全提示，不读取本机文件，也不抛出运行时错误。

## 主窗口桌面壳

主窗口统一使用黑金左侧导航和右侧工作区。首页使用金色火光横幅与四块紧凑炭黑面板，数据由 `HomeDashboard` 和 `toDashboardViewModel()` 从 `PublicTrackerState`、`MatchHistoryResult` 映射；缺日志、未开局、未读历史和错误都显示明确空态，不用演示资讯或胜率补空白。没有配置国服数据源时，天梯面板读取并明确标记 HSGuru 国际服当前补丁排行。左上角只保留 macOS 原生窗口按钮，页面不再绘制第二组装饰按钮。左侧只暴露已有主页面：首页、实时对局、卡牌资料、卡组工具、对局记录和设置；切换页面不会停止日志监听或重置对局状态。

设置页没有二级导航或独立“悬浮窗”页面。基础、悬浮窗、快捷键、外观、其他、数据与隐私、关于七组内容全部放在同一个右侧可滚动内容框中。我方和对手记牌器使用全局开关，设置页不再展示天梯/竞技场切换；旧版两种模式设置不一致时按原天梯开关统一并持久化。浏览器没有桌面 API 时明确显示不可读取，桌面版仍通过 preload API 读取和保存。

基础设置明确告诉用户：普通启动默认显示主窗口，只有主动开启“启动后自动最小化”才在启动时隐藏。“打开软件时将主窗口带到前面”只描述一次性激活；关闭时仍显示主窗口但不抢焦点，开启时只在打开动作发生时带到前面，之后点击炉石或其他软件会正常退后。

悬浮窗设置把位置字段明确命名为“我方记牌器位置 / 我方水平偏移 / 我方垂直偏移”，并提示对手记牌器和英雄胜率窗分别保存自己的位置。首次布局是英雄胜率窗和对手记牌器在左、我方记牌器在右；恢复有效副屏位置时界面不按鼠标屏幕重新排列。

“悬浮窗总开关”关闭全部实战窗和折叠入口；我方、对手全局开关只关闭各自窗口。手动检测模式下，后台状态变化不关闭用户手动打开的我方或对手窗，但这些设置开关仍立即生效。我方关闭按钮在自动模式抑制当前套牌或模式；对手关闭按钮只折叠，奥秘更新只刷新折叠入口，不展开；英雄胜率关闭按钮抑制当前竞技场。界面状态以主进程回传为准，不能提前把“已折叠”画成“已关闭”或“已展开”。

## 卡牌数据库

主程序顶部的书本图标切换“对局面板 / 卡牌数据库”，只切换渲染视图，不暂停日志监听、对局状态或置顶小窗。数据库列表由 `CardLibraryPanel` 承担，`App.tsx` 只维护查询状态和调用 `listCardLibrary()`。

请求固定为分页读取，当前每页 48 张；首次进入读取本地缓存，关键词使用 220ms 防抖，职业和类型筛选、翻页会立即刷新。卡牌源由后台按版本更新后覆盖本地缓存，前端不在每次打开时抓取官网，也不持久化第二份卡牌数据。读取失败时必须保留明确错误，不能回退成示例卡牌或影响正在监听的对局。

## 对局历史

主程序顶部提供独立历史入口，`MatchHistoryPanel` 显示总局数、胜负平、胜率和最近对局。进入页面时通过 `getMatchHistory()` 刷新；加载、空数据、接口缺失、文件错误和无效返回都有明确状态。IPC 返回进入组件前必须经过运行时校验，浏览器预览不会生成示例历史。

## 当前限制

- 对手职业、手牌数、回合等仍是根据现有日志事件推导的近似展示。
- 浏览器预览不能写入日志配置，也不能打开真正的桌面小窗；这些操作需要 Electron 桌面版。
- 浏览器预览不能读取炉石收藏套牌；收藏读取和导入需要 Electron 桌面版提供 preload API。
- 浏览器预览不能读取真实对局历史，也不会伪造记录。

## 2026-07-22 首页与完整设置

首页新增真实数据概览：对局状态、可信天梯推荐、竞技场进度和当前套牌均从现有后台状态映射，缺数据时显示明确空态，不填充参考图里的虚构资讯或排行。停留首页期间如果一局结束，会等待后台保存完成后自动刷新“最近完成”；首次读取和读取失败分别显示真实状态，不再混成未读取空态。

## v0.2.9 生命周期视图

- renderer 只从必填 `cardTracking` 生成当前位置和历史，不再从旧“其他”或对手摘要字段猜区域。
- 我方窗口默认 `100×900`，允许缩到 `100×200`；对手窗口默认 `250×170`。外壳不滚动，唯一列表滚动宿主是主内容。
- 当前位置包含牌库、手牌、场上、奥秘、墓地、移除；历史包含疑似烧毁、已使用。短窗每页只展开一个组，长窗保留用户选择。

- 古神实际结果从对应历史项的 `usageId` 合并，理论候选池只在基础详情字典保存一份。
- 自动奥秘窗口只通过无焦点路径显示；用户主动打开仍可聚焦。
