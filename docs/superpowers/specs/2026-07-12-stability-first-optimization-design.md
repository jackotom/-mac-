# 炉石记牌器稳定性优先全面优化设计

## 目标

在不新增大功能、不推翻现有界面的前提下，把记牌器从“功能丰富但存在状态串台和运行差异”提升为可重复验证、可稳定交付的 Mac 桌面工具。

完成后的核心结果：

- 标准、狂野、竞技场之间切换时，牌库、模式、窗口和识别状态不会互相覆盖。
- 源码运行、开发运行和打包运行使用一致的本机识别组件查找规则。
- 炉石重启、日志暂缺、日志截断、识别失败、断网和缓存损坏时，界面显示真实状态，不沿用旧数据伪装正常。
- 主进程不被重复扫描、网络更新或重计算阻塞，后台空闲占用可测量。
- 所有关键状态变化都有自动测试和真实日志回放证据。

## 范围

### 本次必须完成

1. 修复当前稳定复现的竞技场牌库被普通套牌覆盖问题。
2. 修复开发运行时 `arena-ocr` 和 `frontmost-app` 路径解析不一致。
3. 统一模式与牌库状态的所有权，阻止过期异步识别结果覆盖新状态。
4. 补齐日志会话切换、炉石重启、暂停恢复、缺日志和识别失败的恢复路径。
5. 审查 Electron 窗口安全配置、页面跳转、外部链接和主进程通信入口。
6. 测量并优化启动阶段、空闲监听和高频窗口更新中的明显浪费。
7. 收紧状态提示与悬浮窗信息，优先修复误导、遮挡、裁切和不可恢复操作。
8. 建立发布前的一键验收闭环：测试、检查、构建、真实日志回放、窗口截图、签名和安装包启动。

### 本次不做

- 不新增战绩系统、云同步、账号系统或付费功能。
- 不重新设计整套视觉品牌。
- 不为了整洁而大规模重写已经稳定的日志解析器。
- 不引入新的大型状态管理或界面框架。
- 不伪造国服实时数据；没有可信来源时继续明确显示不可用。

## 总体方案

采用分阶段加固，而不是整体重写。

### 1. 状态正确性

`TrackerService` 继续作为运行状态协调入口，但模式切换必须经过单一状态转换规则。竞技场日志、构筑画面识别、普通对局日志和用户手动操作不能直接互相覆盖。

每次异步扫描、OCR 和会话发现都携带当前运行代次与上下文标识。结果返回时必须再次确认仍属于当前日志会话、当前模式和当前识别任务；不匹配的结果直接丢弃。

模式转换遵循以下优先级：

1. 当前真实对局和当前会话日志。
2. 已确认的竞技场选牌或完整竞技场牌库。
3. 连续确认的标准/狂野选牌画面。
4. 收藏套牌预览。
5. 无法确认时显示等待状态，不沿用旧模式数据。

### 2. 本机识别组件

开发环境从项目内 `native/bin/` 读取组件；打包环境从应用资源目录读取。只根据是否打包选择路径，不能因为 Electron 开发环境也存在资源目录就误判为打包环境。

启动时检查两个组件是否存在、可执行并与当前 Mac 架构匹配。失败时说明缺失的是哪个组件以及可执行的恢复动作。构建脚本和安装包验收复用同一套检查。

### 3. 日志与错误恢复

日志监听保留当前“新会话优先”的规则，同时增加明确的状态转换测试：

- 新会话暂时没有 `Power.log`。
- `Player.log` 已开局但 `Power.log` 停更。
- 炉石重启并创建新目录。
- 日志被截断或重新创建。
- 从竞技场返回标准/狂野。
- 用户暂停后，旧扫描结果延迟返回。

错误分为可自动恢复、需要用户操作和数据不可用三类。可恢复错误保留重试但不得刷屏；需要用户操作时显示一步式说明；数据不可用时清空可能误导的旧值。

### 4. 安全与数据边界

按 Electron 官方清单核对：页面隔离、沙箱、渲染层权限最小化、页面跳转限制、新窗口限制、外部链接白名单、主进程通信来源校验和严格内容策略。

所有网络数据先在主进程验证结构和版本，再进入界面。卡牌图片只作为图片资源加载，失败不影响记牌。屏幕截图只存在临时目录，识别完成或失败都删除。

### 5. 性能

先测量再改动。记录冷启动到监听开始、空闲一分钟的进程占用、日志突发时的更新时间和窗口刷新次数。

优化重点：

- 启动时只加载监听必须的数据，卡牌库和远程更新延后。
- 合并重复状态推送与重复窗口刷新。
- 避免多个定时器同时执行同类前台检测和会话扫描。
- 网络更新、OCR 和大文件解析不阻塞窗口控制。
- 不为未经测量的问题引入工作线程或新依赖。

### 6. 界面体验

保持现有紧凑桌面工具方向，只处理稳定性相关体验：

- 模式、日志和错误状态使用一致的短文案。
- 正在识别、缺日志、权限被拒绝和数据过期不能看起来像正常监听。
- 小窗不能显示与当前模式无关的旧牌库、旧评分或旧统计。
- 300×400、300×500、420×1000 和主窗口 900×620 都做截图验收。
- 键盘操作、焦点、关闭后恢复和不抢炉石焦点需要实测。

## 测试与验收

### 自动检查

- 当前失败用例先保持失败证据，再修到通过。
- 为每个状态转换新增回归测试，包含延迟异步结果和重复日志通知。
- 运行完整测试、双重类型检查和正式构建。
- 测试不得保留 React 更新警告或未处理的异步任务。

### 真实运行

- 使用项目内普通对局、自动匹配和竞技场日志回放。
- 使用本机当前炉石日志验证最新会话发现，但不修改真实游戏数据。
- 依次打开主窗口、记牌小窗、对手窗、竞技场评分窗、天梯推荐窗和场攻层，截图并检查内容与边界。
- 验证开发运行能找到本机识别组件；验证打包版包含并能调用组件。
- 重新生成 Apple Silicon 安装包，检查签名、录屏说明和实际启动。

## 分工与验收责任

- 主控：拆分、整合、运行完整验收，不合格任务打回。
- 前端：渲染状态、窗口同步、错误提示和刷新性能。
- 后端：日志、模式状态机、OCR、缓存、网络与主进程安全。
- UI/体验：主窗口和悬浮窗在真实尺寸下的信息正确性与操作恢复。
- 测试：状态转换矩阵、真实日志回放、安装包验收脚本。
- 代码审查：只读审查完整改动，重点查竞态、静默失败、过度复杂和安全退化。

每个子控必须报告修改内容、实际验证、仍可能存在的风险。子控完成不代表交付完成，只有主控复测通过才算完成。

## 依据

- Electron 官方安全指南：最小权限、上下文隔离、沙箱、页面导航限制和通信来源校验。
- Electron 官方性能指南：先测量、延后非必要工作、避免阻塞主进程和渲染进程。
- React 官方指南：减少可派生状态和不必要的副作用，确保订阅正确清理。
- Apple Human Interface Guidelines：Mac 窗口、焦点、状态反馈和可访问性遵循平台习惯。
- 项目现有 `docs/commercial-acceptance.md`：真实日志、打包版、签名和安装路径是最终交付标准。
